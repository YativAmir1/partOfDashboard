1. סקירה כללית ברמה גבוהה
--------------------------

לוח בקרה עירוני מבוסס Next.js 16 / React 19 עבור עיריית רמת גן. המערכת היא
פרונטאנד בלבד — אין קריאות API, אין שרת, אין מסד נתונים. כל הנתונים הם
קבצי JSON סטטיים הנטענים בזמן בנייה. ממשק המשתמש בעברית (RTL, גופן Heebo)
ומדמה מערכת בקרה עירונית מבוססת בינה מלאכותית על פני שישה מסכים.

סטאק טכנולוגי:
  - Next.js App Router
  - React 19
  - TypeScript
  - Tailwind CSS v4
  - shadcn/ui
  - Recharts (גרפים)
  - Leaflet (מפות)
  - Playwright (בדיקות E2E)

7. זרימת נתונים וסקירת נתוני דמה
-----------------------------------

קבצי JSON סטטיים / .ts (data/)
          ↓
   lib/data.ts (קבועים, טעינות)
          ↓
   הוקים מותאמים (hooks/) — פילטר, אגרגציה, חישוב
          ↓
   דפי פייג' (app/*/page.tsx) — state מקומי (שכונה נבחרת, פילטר)
          ↓
   רכיבי תכונה (components/*/) — תצוגה בלבד

שתי זרימות גלובליות חוצות-מערכת:
  1. DemoContext — מצב תרחיש מוזרק ל-~8 רכיבים שונים בכל הדפים במקביל
  2. HazardContext — טיימר משותף בין הטוסט לכל רכיב שמסנן את אירוע התאונה

אין קריאות רשת בשום מקום בקוד. כל ההוקים קוראים מ-JSON מיובא מקומית.

9. מוכנות לצד שרת (Backend Readiness)
---------------------------------------

הקוד בנוי עם תפרים נקיים מאוד לחיבור עם צד שרת.

א. שליפת נתונים
   כל הוק מייבא JSON ישירות. כל הוק יצטרך להיות מוחלף
   בקריאת fetch / SWR / React Query לנקודת קצה של API.
   חתימות ההוקים וצורות הנתונים המוחזרות כבר יציבות —
   רכיבי הדפים לא יצטרכו להשתנות.

ב. זמן אמת
   useLiveTicker ו-DemoContext מדמים אירועים חיים בטיימרים.
   אלה יוחלפו ב-WebSocket או ב-SSE.
   מבנה ה-Context כבר מבודד היטב.

ג. טיפוסים
   lib/types.ts הוא כבר חוזה API יציב.
   הממשקים ממפים בצורה נקייה למשאבי REST:
   /incidents, /complaints, /tasks, /cameras וכו'.

ד. אימות
   אין שכבת אימות בשום מקום. הוספת session-based או JWT
   תדרוש עטיפת ה-layout השורש והוספת middleware.

ה. פעולות כתיבה (Mutations)
   אין פעולות כתיבה כרגע — אין טפסים שמגישים לשום מקום.
   שיגור המשימה בדמו הוא קוסמטי בלבד. כל פעולה מדומה
   (שגר משימה, עדכן סטטוס) תהפוך ל-POST / PATCH אמיתי.

ו. משתני סביבה
   next.config.ts מגביל את כתובת הפיתוח ל-127.0.0.1 בלבד.
   אין משתן NEXT_PUBLIC_API_URL או דומה מוגדר בשום מקום.

סיכום:
   הפרונטאנד בנוי היטב ואגנוסטי לצד שרת. העבודה העיקרית
   היא להחליף 9 הוקים (אחד לכל תחום נתונים) בקריאות fetch
   אמיתיות, לחבר שכבת WebSocket או polling לאירועים חיים,
   ולהוסיף middleware לאימות.
